FEATURES

Everything that happens to an issue stays in the project.

Aether connects your team's daily work with planning and administration. Start with issues and boards, then configure the details around the way you work.

BoardsBacklogs and sprintsWorkflowsIssues and collaborationTime trackingPermissionsSearchReleases and componentsReportsMoving your dataAPI and extensionsHistory and audit

Boards

Adapt the board to your team’s process.

Arrange columns around workflow states. Filter issues and split them into swimlanes so each review can focus on the relevant team, epic or scope of work.

  • Map states to columns
  • Quick filters and swimlanes
  • Work in progress limits (WIP)
  • Move cards under workflow rules

Backlogs and sprints

Plan a sprint with a goal and scope.

Choose issues from the backlog, set a goal and estimate the work. When the sprint ends, move unfinished issues back to the backlog or into another planned iteration.

  • Planned, active and completed sprints
  • Sprint goals, dates and scope
  • Story points and time estimates
  • Scope change history

Workflows

Define when an issue can change state.

A task may need review, more information or approval. Define states and transitions, with required fields that specify what must be ready before the next step.

  • Custom states and transitions
  • Requirements for changing state
  • Versioned workflow definitions
  • Issue migration between workflow versions

Issues and collaboration

Descriptions, conversations and files with each issue.

Bring descriptions, priorities and assignees together with comments and files. Epics, subtasks and links show how an individual issue relates to the wider project.

  • Issue types and custom fields
  • Epics, issues and subtasks
  • Links including blockers and duplicates
  • Comments, attachments and notifications

Time tracking

Time records linked to specific tasks.

Start a timer or enter time worked against an issue. Collect entries into a period and submit it for approval. Later corrections preserve the change history.

  • Timer and manual entries
  • Time summaries and CSV export
  • Submit periods for approval
  • Corrections with preserved history

Permissions

Define who sees a project and what they can change.

Invite your team and define project access. Roles, groups and permission schemes separate viewing a project, working on issues and project administration.

  • Access for people and groups
  • Viewer, member and administrator roles
  • Separate permissions for issue actions
  • Control access to time entries
  • SSO (OIDC) and MFA sign-in

Search

Find issues and save the filters you need.

Search issue content and project fields. Saved filters and the LQL query language help you return to your own work, the team's issues or a particular release.

  • Issue search and filtering
  • Private and shared filters
  • LQL queries
  • A view of work assigned to you

Releases and components

Assign issues to releases and components.

Link issues to a version to see what is ready and what still needs work. Components organise tasks by product area.

  • Versions and release scope
  • Issue completion status
  • Project components
  • Link tasks to product areas

Reports

Review project progress and sprint delivery.

Check issue flow, completion times and sprint progress. Look at ageing tasks and current blockers to understand where to focus attention.

  • Issue flow and lead/cycle times
  • Velocity, burnup and burndown
  • Release progress
  • Tables explaining the measures shown

Moving your data

Bring your issues over from Jira.

Bring issues over from Jira using an export file, or load data in Aether’s format. Match the fields and check a trial result before moving data into the project.

  • Bring Jira issues over
  • Match fields to your project
  • Check data before importing
  • Result reports and resumable imports

API and extensions

Connect Aether to your team’s tools.

Use the REST API and extensions to exchange data and connect tools. Administrators define integration access and approve the permissions requested by installed packages.

  • REST API
  • Scoped tokens
  • Installable extensions
  • Approval of integration permissions

History and audit

Review changes and actions.

Issue history shows how work progressed, while the audit trail records system actions. Use that context to explain a change and understand what happened in a project.

  • Issue change history
  • User action log
  • Audit filters
  • Audit export to CSV
